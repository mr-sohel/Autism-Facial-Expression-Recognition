# Agent Context: Autism Facial Expression Recognition (ASD FER) Project

This document provides guidelines and context for AI agents assisting with this repository.

## Mission
The overarching goal of this project is to implement a robust, Q1 publication-grade machine learning pipeline for Autism Spectrum Disorder (ASD) Facial Emotion Recognition. 

## Codebase Principles
1. **Rigor over Hype**: The pipeline values subject-independent splits, cluster-bootstrapping for confidence intervals, and strict significance tests (McNemar). Avoid suggesting standard "image-level splitting" or "random splits" as it leaks identities and artificially inflates accuracy.
2. **Reproducibility**: The evaluation script (`asd_fer_baseline.py`) produces `.npz` files that contain the per-image probabilities. All downstream metrics and figures are derived **only** from these `.npz` files (via `--analyze-only`). Do not attempt to calculate metrics dynamically inside the training loop.
3. **Journal Standards**: 
   - Figures generated by `asd_fer_figures.py` strictly adhere to constraints for Q1 journals (e.g., no dual-axes, colorblind-safe palettes, small-multiples for overlapping curves). Do not alter these design rules.
   - We prefer interpretable and smaller foundation models over massive LLM/VLMs since the development set is only ~1,700 images.

## Architecture
- **`src/build_manifest.py`**: Must be run whenever a new dataset is added. Handles exact and near-duplicate detection via image hashing, and identity clustering via FaceNet.
- **`src/asd_fer_baseline.py`**: The core benchmark script. Uses `StratifiedGroupKFold` over the identities discovered by the manifest builder.
- **`src/asd_fer_zoo.py`**: Model registry. Rather than hardcoding models in the baseline script, they are registered here. Agents should modify this file to add new architectures (such as hemiface-split encoders).
- **`src/asd_fer_figures.py`**: Generates publication-ready figures.

## Agent Guidelines
1. **Running Python Scripts**: Python scripts should always be executed from the root directory using the `src/` prefix so that module imports resolve correctly (e.g., `python src/asd_fer_baseline.py`).
2. **Adding New Models**: When asked to add a new model, modify `src/asd_fer_zoo.py` and register it inside `MODEL_ZOO`. Ensure that it uses appropriate initialization techniques (like LoRA or frozen features) if the model is large.
3. **Data Handling**: Raw data should remain in `data/raw/` and processed output (e.g., unzipped folders) inside `data/processed/`. Never commit `.npz` or image files to git.
4. **Modifying the Code**: When proposing structural changes, always consider the strict evaluation requirements. Never remove the locked held-out test evaluation or the cluster bootstrap CI.
